# Мой дом — Smart Home Mobile

Начальная версия Android-клиента для личного сервера Home Assistant.
Это самостоятельный клиент REST API, а не копия Home Assistant Companion.

## Реализовано в исходниках
- Подключение к адресу Home Assistant с токеном пользователя.
- Хранение токена: AES-GCM, ключ в Android Keystore; резервное копирование отключено.
- Список light, switch, sensor, binary_sensor, climate, camera, scene.
- Команды включения/выключения света и реле, запуск сцен с подтверждением.
- Ручное обновление; недоступные сущности не имеют кнопок управления.
- Открытие одной настроенной RTSP-камеры в установленном VLC, авторизация камеры в VLC.
- Открытие полной панели Home Assistant в браузере.
- GitHub Actions: lint, сборка debug APK, выгрузка артефакта.

## Текущий статус

Android Lint и испытание на телефоне НЕ выполнены. Workflow ещё не запускался.
Перед установкой необходимо дождаться успешной сборки Actions.
Нет встроенного видео, настройки температуры, уведомлений, архива, автоматического
обновления, OAuth-входа и нескольких профилей камер. Эти функции — следующие этапы.
Изменение отопления пока доступно только в полной панели Home Assistant.

## Первый запуск
1. Установить Home Assistant OS на подходящий Raspberry Pi, закончить первичную настройку.
2. Добавить устройства и RTSP-камеру через интерфейс Home Assistant; проверить управление там.
3. Создать отдельного пользователя для телефона. В профиле создать долгоживущий токен.
4. Установить APK из Actions → Android APK → успешный запуск → Artifacts → SmartHomeMobile-debug.
   Артефакт скачивается ZIP: извлечь APK на телефоне.
5. В приложении указать адрес HA и токен. Пример адреса: http://homeassistant.local:8123.
6. Указать RTSP-адрес своей камеры без логина и пароля. Авторизация выполняется в VLC.
7. Нажать «Обновить устройства». Проверить одну лампу или тестовое реле.

Приложение работает с сервером Home Assistant, не с облачным аккаунтом iCSee/Tuya.
Поддержка конкретных Tuya-устройств и работа без интернета проверяются отдельно.

## Сборка
JDK 17, Gradle 8.11.1, Android SDK 35, Build Tools 35.0.0, AGP 8.9.2.

```sh
gradle :app:lintDebug :app:assembleDebug
```

Gradle Wrapper пока не включён; CI устанавливает фиксированную версию Gradle.
APK: app/build/outputs/apk/debug/app-debug.apk.
Минимальная версия телефона Android 8.0 (API 26).
Debug-подпись CI может изменяться между сборками. Для обновлений с сохранением данных
нужен постоянный ключ подписи в GitHub Secrets; его настройка запланирована до регулярных релизов.

## GitHub
Создать приватный репозиторий smart-home-mobile под своим аккаунтом.
После загрузки исходников в main workflow запустится автоматически.
Не загружать сам ZIP как единственный файл: GitHub должен видеть .github/workflows/android.yml.

## Безопасность
- Не добавлять токены, пароли, серийные номера камер и видеозаписи в Git.
- В примерах отсутствуют реальные данные пользователя.
- HTTP разрешён для домашней сети/VPN. Не использовать HTTP с токеном через публичный интернет.
- TLS-сертификаты проверяются стандартной системой Android; обхода проверок нет.
- API-перенаправления отключены: токен не отправляется на другой адрес автоматически.
- Внешний доступ настраивать через VPN или HTTPS. Открывать порты камеры в интернет не требуется.
- При сетевом сбое команда могла выполниться; повторно обновить состояние перед повторной командой.
- Отзыв токена выполняется в профиле Home Assistant.
